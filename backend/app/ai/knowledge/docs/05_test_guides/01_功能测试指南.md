# 功能测试指南

## 测试策略

### 测试分层
1. **冒烟测试**：核心流程可用性验证，P0 用例全量执行
2. **功能测试**：按需求逐个功能点验证，P0+P1 全量 + P2 选择执行
3. **回归测试**：修复缺陷后的影响范围验证，P0+P1 全量回归
4. **验收测试**：交付前的全面验证，全优先级执行

### 测试顺序建议
1. 先测核心流程（创建→查看→编辑→删除的 CRUD 闭环）
2. 再测业务规则（状态流转、数据校验、业务约束）
3. 后测异常与边界（非法输入、极端场景）
4. 最后测权限与兼容（角色权限、浏览器兼容）

## MobTestPlatform 模块测试要点

### 认证与账户
- 重点：登录/登出的 Session 管理、密码安全、权限边界
- 易漏：多标签页 Session 同步、并发登录限制、密码复杂度校验

### 项目管理
- 重点：CRUD 完整性、成员角色管理、级联删除
- 易漏：项目名称唯一性校验、Owner 不可移除、删除项目后数据清理

### 用例管理
- 重点：树形结构操作、用例 CRUD、脑图编辑、AI 生成
- 易漏：拖拽移动的层级限制、批量操作事务性、回收站还原冲突

### 测试任务
- 重点：任务创建与用例快照、手工执行状态流转、执行统计
- 易漏：快照冻结后编辑原用例是否影响任务、并发执行、执行中断恢复

### 测试报告
- 重点：数据汇总准确性、导出格式完整性
- 易漏：空数据报告、大量用例的报告性能、通过率计算精度

### 设备管理
- 重点：Agent 注册与绑定、设备发现、心跳保活
- 易漏：Agent 离线后的任务调度、绑定码有效期、设备状态并发更新

### 消息中心
- 重点：实时推送准确性、已读状态管理
- 易漏：Socket.IO 断线重连、大量通知性能、清空操作不可恢复的二次确认

## 测试数据准备

### 基础数据
- 至少 4 个不同角色的测试账号（super/manager/tester/admin）
- 至少 2 个测试项目（含不同状态）
- 每个项目下至少 1 个迭代和若干需求

### 边界数据
- 空项目（无迭代、无用例）
- 大数据量项目（100+ 用例、10+ 用例集）
- 特殊字符数据（中文、emoji、HTML标签）

## 缺陷提交规范

提交缺陷时应包含：
1. **标题**：简明描述现象（如"项目管理-删除项目后用例集数据残留"）
2. **环境**：浏览器版本、操作系统
3. **前置条件**：复现前的数据和配置状态
4. **复现步骤**：具体操作步骤
5. **实际结果**：附截图或日志
6. **预期结果**：根据需求文档的正确行为
7. **严重等级**：S1-S4
