# 用例评审功能需求文档

## 1. 功能概述

用例评审是测试管理平台中保障用例质量的核心流程。评审发起人选择待评审的用例集，指定评审人，评审人对用例逐条进行通过或驳回操作，评审完成后生成评审记录。

## 2. 角色定义

| 角色 | 权限 |
|------|------|
| 评审发起人 | 发起评审、查看评审状态、重新发起评审 |
| 评审人 | 对分配给自己的用例执行通过/驳回操作、填写评语 |
| 项目管理员 | 查看项目下所有评审任务 |

## 3. 功能需求

### 3.1 发起评审

- 入口：在用例管理页选中一个用例集，点击「发起评审」按钮
- 必填信息：
  - 评审人（从项目成员中选择，支持多选）
  - 评审范围：默认为当前用例集全部用例，可手动勾选部分用例
- 可选信息：
  - 评审截止日期
  - 评审说明/备注
- 校验规则：
  - 用例集为空时不允许发起
  - 评审人不能为空
  - 同一用例集如有「进行中」的评审任务，给予提示但仍允许发起新的

### 3.2 评审中心

评审中心是评审人和发起人管理评审任务的页面，包含三个分组标签页：

| 标签页 | 说明 |
|--------|------|
| 待我评审 | 当前用户作为评审人且状态为「进行中」的任务 |
| 我发起的 | 当前用户发起的所有评审任务 |
| 已完成 | 状态为「已完成」或「已驳回」的评审任务 |

每条评审任务显示：用例集名称、发起人、评审人、发起时间、状态、进度（已审/总数）。

### 3.3 逐条评审

评审人进入评审任务后：

1. 看到用例列表，每条用例显示用例名称、优先级、步骤、预期结果
2. 对每条用例执行以下操作之一：
   - **通过**：该用例标记为「已通过」
   - **驳回**：该用例标记为「已驳回」，必须填写驳回理由（至少10个字）
3. 支持批量操作：全选后批量通过
4. 已审批的用例允许修改结果（在评审未完成前）

### 3.4 完成评审

- 当所有用例都已审批（无待审用例），评审人可点击「完成评审」
- 完成后：
  - 评审任务状态变为「已完成」
  - 系统向评审发起人发送站内通知
  - 记录评审历史快照（包含每条用例的审批结果和评语）

### 3.5 评审历史

- 评审任务完成后，可在详情页查看「评审历史」标签
- 历史记录包含：评审人、审批时间、每条用例的通过/驳回状态、驳回理由
- 同一用例集的多轮评审历史按时间倒序排列

### 3.6 驳回后重新发起

- 评审完成后，如有用例被驳回，发起人可以修改被驳回的用例后，对同一用例集再次发起评审
- 新评审任务与历史评审相互独立

## 4. 非功能要求

- 评审列表加载时间 < 2秒（50条用例以内）
- 评审数据与用例数据实时同步，不存在脏读

## 5. 界面交互

### 发起评审弹窗

```
┌──────────────────────────────────────┐
│ 发起评审                              │
│                                      │
│ 用例集：[xxxx 用例集]（只读）          │
│ 评审人：[下拉多选项目成员]  *必填       │
│ 截止日期：[日期选择器]                  │
│ 评审说明：[多行文本框]                  │
│                                      │
│         [取消]     [发起]             │
└──────────────────────────────────────┘
```

### 逐条评审页面

用例以列表形式展示，每行包含：
- 复选框（用于批量操作）
- 用例编号、用例名称、优先级标签
- 展开后显示：前置条件、操作步骤、预期结果、测试数据
- 操作列：[通过] [驳回] 按钮
- 驳回时展开评语输入框

顶部显示进度条：已审 X / 共 Y 条

## 6. 接口清单

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/review/create` | POST | 发起评审任务 |
| `/api/review/list` | GET | 获取评审任务列表（支持按状态筛选） |
| `/api/review/{id}` | GET | 获取评审任务详情 |
| `/api/review/{id}/approve` | POST | 通过单条用例 |
| `/api/review/{id}/reject` | POST | 驳回单条用例（含理由） |
| `/api/review/{id}/batch-approve` | POST | 批量通过 |
| `/api/review/{id}/complete` | POST | 完成评审 |
| `/api/review/{id}/history` | GET | 获取评审历史 |
