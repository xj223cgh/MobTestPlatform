# 平台访问与 Agent 流程说明（服务器 + 多用户）

## 一、整体架构

```
                    ┌─────────────────────────────────────────────────────────┐
                    │                    平台服务器                              │
                    │  ┌─────────────┐    ┌─────────────┐    ┌───────────────┐  │
                    │  │  前端 (Vue) │    │ 后端 (Flask)│    │ MySQL / 存储  │  │
                    │  │  端口 8081  │───▶│  端口 5000  │───▶│               │  │
                    │  └─────────────┘    └──────┬──────┘    └───────────────┘  │
                    │                            │                              │
                    │                    可选：服务器本机 adb                     │
                    │                    （未绑定 Agent 时用）                    │
                    └────────────────────────────┼──────────────────────────────┘
                                                 │
         ┌──────────────────────────────────────┼──────────────────────────────────────┐
         │                                      │                                       │
         ▼                                      ▼                                       ▼
┌─────────────────┐                  ┌─────────────────┐                    ┌─────────────────┐
│  用户 A 的电脑   │                  │  用户 B 的电脑   │                    │  用户 C 的电脑   │
│  浏览器访问平台  │                  │  浏览器访问平台  │                    │  仅浏览器访问   │
│  运行 Agent     │                  │  运行 Agent     │                    │  不运行 Agent   │
│  (USB 设备在这)  │                  │  (USB 设备在这)  │                    │                 │
└────────┬────────┘                  └────────┬────────┘                    └────────┬────────┘
         │ 设备列表来自本机 adb                  │ 设备列表来自本机 adb                  │ 设备列表来自
         │ (Agent 上报)                         │ (Agent 上报)                         │ 服务器本机 adb
         └─────────────────────────────────────┴─────────────────────────────────────┘
```

- **平台**：前端 + 后端 + 数据库部署在同一台**服务器**上（或前后端分离部署，用户统一访问前端入口）。
- **用户**：通过**浏览器**访问平台地址（如 `http://服务器IP:8081`），可在**任意一台电脑**上访问。
- **本机 Agent**：在**用户当前使用的那台电脑**上运行，用于在该电脑上执行 adb/scrcpy，设备列表、投屏等来自**运行 Agent 的那台机器**的 USB/无线设备。

## 二、当前流程概览

### 2.1 服务器侧

1. **部署**：将项目（backend、frontend、agent/dist/）部署到服务器，按 README 配置数据库与 `.env`。
2. **启动**：运行 `python start.py` 或分别启动后端（5000）、前端（8081）。若需外网/内网访问，需保证防火墙或反向代理放行对应端口。
3. **Agent 安装包**：在服务器项目目录下放置 `agent/dist/MobTestAgent.exe`，平台会提供「下载 Agent」入口，用户从浏览器下载到**自己的电脑**再运行。

### 2.2 用户通过浏览器访问平台

| 步骤 | 说明 |
|------|------|
| 1. 打开平台 | 用户在**任意电脑**上打开浏览器，访问 `http://服务器IP:8081`（或配置的域名），登录账号。 |
| 2. 进入设备管理 | 进入「设备管理」页。此时会请求后端：**当前登录用户是否已绑定本机 Agent、该 Agent 是否在线**。 |
| 3. 设备列表来源 | 见下表「设备列表来源规则」。 |
| 4. 绑定本机 Agent（可选） | 若用户希望**在当前使用的这台电脑**上管理 USB 设备，需在这台电脑上**运行 MobTestAgent.exe**，并在平台页点击「本机 Agent」→ 绑定/自动绑定。绑定后，设备列表与投屏等均来自**这台电脑**的 adb。 |

### 2.3 设备列表来源规则（关键）

| 条件 | 设备列表来源 | 说明 |
|------|--------------|------|
| 当前用户**已绑定**本机 Agent，且该 Agent **在线**（WebSocket + 心跳正常） | **绑定 Agent 所在机器**的 adb | 即「用户运行 Agent 的那台电脑」上的 `adb devices`，由 Agent 执行并返回给平台。 |
| 当前用户**未绑定** Agent，或已绑定但 Agent **不在线** | **服务器本机**的 adb | 后端在服务器上执行 `adb devices`，列表是插在**服务器**上的设备。 |

因此：

- **用户 A** 在办公室电脑运行 Agent 并绑定 → 用户 A 在设备管理页看到的设备是**办公室电脑**连接的设备。
- **用户 B** 在家用电脑运行 Agent 并绑定 → 用户 B 看到的设备是**家用电脑**连接的设备。
- **用户 C** 不运行 Agent、仅用浏览器访问 → 看到的是**服务器本机**连接的设备（若服务器上装了 adb 且接了设备）。

每个用户**最多绑定一台 Agent**（绑定关系在平台侧：用户 ↔ Agent 一对一）；换电脑使用时，在新电脑上运行 Agent 并重新绑定即可（会覆盖原绑定）。

## 三、其他用户 / 多用户访问要点

1. **账号与绑定独立**  
   每个登录用户有自己的「本机 Agent 绑定」状态。用户 A 绑定的是 A 运行 Agent 的电脑，用户 B 绑定的是 B 运行 Agent 的电脑，互不影响。

2. **同一用户多台电脑**  
   若同一用户有时在办公室、有时在家：  
   - 在**办公室电脑**打开平台并运行 Agent → 绑定后，设备列表来自办公室电脑。  
   - 在**家里电脑**打开平台并运行 Agent → 再次绑定会**覆盖**之前的绑定，设备列表变为家里的电脑。  
   即：**同一时刻一个用户只对应一台 Agent（一台电脑）**。

3. **服务器上的设备**  
   若 Android 设备 USB 接在**服务器**上，则只有「未绑定 Agent 或 Agent 不在线」的用户会看到这些设备（因为此时用的是服务器本机 adb）。若希望某用户专门看服务器上的设备，该用户**不要绑定**本机 Agent，或先解绑即可。

## 四、Agent 连接的是「平台服务器」

Agent 启动时需要连接**平台后端**（注册、心跳、绑定、接收任务都走后端）：

- Agent 默认连接：`http://127.0.0.1:5000`（即本机 5000 端口）。
- 当平台部署在**服务器**上时，用户必须在**运行 Agent 的那台电脑**上把地址改为服务器地址，否则 Agent 会连本机 5000，无法连上平台。

**正确用法（平台在服务器时）：**

- 方式一：运行前设置环境变量  
  `AGENT_BASE_URL=http://服务器IP:5000`  
  然后运行 `MobTestAgent.exe`。
- 方式二：命令行参数  
  `MobTestAgent.exe --base-url http://服务器IP:5000`

例如平台地址为 `http://192.168.1.100:8081`（前端），则后端一般为 `http://192.168.1.100:5000`，Agent 应使用：

```text
MobTestAgent.exe --base-url http://192.168.1.100:5000
```

这样 Agent 才能注册、心跳、绑定并接收设备任务。**一键绑定 / 自动绑定**也是在前端（用户浏览器）与本机 Agent（127.0.0.1:8765）之间完成的，但 Agent 与平台的通信始终是 Agent → 服务器后端。

## 五、流程简图（按角色）

**服务器管理员：**

```text
部署项目 → 启动后端 + 前端 → 放置 agent/dist/MobTestAgent.exe → 用户可下载
```

**任意用户（在任意电脑上）：**

```text
浏览器打开 http://服务器IP:8081 → 登录 → 设备管理
  ├─ 不运行 Agent → 看到的是「服务器本机」的设备列表
  └─ 要在本机管理 USB 设备 →
       1) 下载 MobTestAgent.exe（从平台）
       2) 在本机运行：MobTestAgent.exe --base-url http://服务器IP:5000
       3) 在设备管理页点击「本机 Agent」→ 绑定（或等待自动绑定）
       4) 之后设备列表、投屏等来自本机
```

**多用户：**

- 用户 A、B、C 各自登录，各自可选是否在本机运行 Agent 并绑定。
- 设备列表始终遵循上文「设备列表来源规则」：已绑定且在线 → Agent 所在机器；否则 → 服务器本机。

## 六、小结表

| 问题 | 答案 |
|------|------|
| 平台部署在哪？ | 前端 + 后端在**服务器**；用户用浏览器访问服务器地址。 |
| 设备列表从哪来？ | 已绑定且在线的 Agent → **该 Agent 所在电脑**的 adb；否则 → **服务器本机**的 adb。 |
| 其他用户访问同一平台？ | 可以；每人独立登录、独立绑定状态，互不影响。 |
| Agent 应连哪里？ | 必须连**平台后端**（服务器）。平台在服务器时用 `--base-url http://服务器IP:5000`。 |
| 自动绑定怎么生效？ | 用户浏览器访问平台且未绑定时，前端轮询本机 127.0.0.1:8765；本机运行 Agent 后会自动完成绑定（无需再点「绑定本机」）。 |

以上为当前「服务器 + 其他用户访问平台」的完整流程与约定。
