# 平台访问与 Agent 流程说明

适用于：**平台部署在服务器**、多名测试人员用**浏览器**访问、设备可能接在**各用户本机**的场景。

## 架构要点

```
平台服务器：前端(8081) + 后端(5000) + MySQL
     │
     ├─ 用户 A：浏览器 ── 可选：本机运行 Agent（USB 设备接在 A 的电脑）
     ├─ 用户 B：同上
     └─ 用户 C：仅浏览器（未绑 Agent 时列表来自服务器本机 adb）
```

- **Agent** 跑在用户**当前操作电脑**上，负责该机的 `adb`/投屏指令；与平台后端的通信必须指向**服务器后端地址**，而非 `127.0.0.1`（除非平台也在本机）。

## 设备列表来源（核心规则）

| 条件 | 设备列表来自 |
|------|----------------|
| 当前用户已绑定本机 Agent，且 Agent **在线** | Agent 所在机器的 `adb devices` |
| 未绑定或 Agent **离线** | **服务器本机**的 `adb devices` |

同一用户**同一时间**只绑定一台 Agent；在新电脑运行 Agent 并再次绑定会覆盖原绑定。

## 部署与下载

1. 服务器部署 `backend`、`frontend`，`agent/dist/` 下放置 `MobTestAgent.exe`，供用户从页面下载。
2. 启动：`python start.py` 或分别启动后端与前端；防火墙/反代放行 5000、8081。

## 用户侧：Agent 指向服务器

Agent 默认连 `http://127.0.0.1:5000`；平台在服务器上时必须改为服务器后端，例如：

```text
set AGENT_BASE_URL=http://192.168.1.100:5000
MobTestAgent.exe
```

或：`MobTestAgent.exe --base-url http://192.168.1.100:5000`

前端「一键绑定 / 自动绑定」是浏览器与本机 Agent（如 `127.0.0.1:8765`）交互；**Agent 与平台的业务连接始终是 Agent → 服务器后端**。

## 多用户小结

| 问题 | 结论 |
|------|------|
| 多人同时用同一平台？ | 可以；账号与 Agent 绑定相互独立。 |
| 设备列表不一致？ | 正常：每人看到的是「自己的 Agent 机」或「服务器 adb」。 |
| 设备接在服务器上？ | 不绑 Agent 的用户会看到服务器本机设备。 |
