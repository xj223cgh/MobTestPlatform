# 功能埋点与角色权限可视化配置设计方案

## 一、目标与定位

- **目标**：对指定模块做可配置的「功能埋点」，通过为不同角色勾选这些埋点，实现灵活的权限分配。
- **当前策略**：**仅对以下 5 个模块做权限配置**，其余功能仅需登录即可使用，不做角色级权限限制。
  1. 项目管理：项目的增、删、改
  2. 迭代管理：迭代的增、删、改
  3. 需求管理：需求的增、删、改
  4. 权限配置：入口、管理员/测试人员/普通成员分别可配置
  5. 用户管理：入口、用户的增、删、改、编辑用户
- **效果**：管理员在「角色权限配置」页面对每个角色勾选其可用的功能点；用户仅拥有其所属角色被勾选的功能，菜单与操作据此显隐，接口据此鉴权。

---

## 二、设计思路概览

1. **功能埋点**：仅对上述 5 个模块枚举可授权操作（如「项目-新建」「用户-编辑」），每个最小单元一个埋点编码。
2. **角色与埋点绑定**：每个角色对应一个「埋点集合」；在「角色权限配置」界面为角色勾选/取消勾选埋点，持久化到 `role_permissions` 表。
3. **用户与角色绑定**：用户关联到某一角色；用户有效权限 = 其角色所配置的埋点集合。
4. **前端与后端一致**：前端根据用户有效埋点控制 5 个模块的菜单与按钮显隐；后端仅对这 5 个模块相关接口做埋点鉴权，无权限则返回 403。

## 三、功能模块与埋点划分（当前仅 5 个模块）

### 3.1 项目管理

| 埋点编码 | 功能说明 |
|----------|----------|
| `project.list` | 入口（左侧菜单是否显示） |
| `project.create` | 新建项目 |
| `project.edit` | 编辑项目 |
| `project.delete` | 删除项目 |

### 3.2 迭代管理

## 四、埋点与路由/操作的对应关系

- **菜单可见性**：仅对 5 个模块的路由设置 `meta.permissions`；用户至少拥有对应入口埋点才显示该菜单并允许访问。
- **页面内操作**：列表上的「新建/编辑/删除」等按钮根据 `project.create`、`user.edit` 等埋点显隐。
- **接口鉴权**：仅对 5 个模块相关接口使用 `@permission_required('xxx')` 或 `has_permission(..., 'xxx')`；无权限返回 403。

---

## 五、角色与权限配置的数据与交互

- **存储**：`role_permissions` 表，字段 `role` + `permission_code`。全量埋点清单来自 `backend/app/constants/permissions.py` 的 `PERMISSION_GROUPS`（仅含上述 5 个模块）。
- **超管**：不查配置表，代码中视为拥有全部埋点；配置页禁止编辑超管权限。
- **默认配置**：`DEFAULT_ROLE_PERMISSIONS` 中为 manager / tester / admin 定义默认埋点；数据库无该角色记录时使用。执行 `database/06_seed_role_permissions.py` 可清理废弃埋点并为无配置角色写入默认。

---

## 六、默认角色权限规划（已实现）

| 角色 | 默认权限范围说明 |
|------|------------------|
| **超管 super** | 不查配置表，始终拥有全部埋点；不可在「角色权限配置」中修改。 |
| **管理员 manager** | 5 个模块的全部埋点：项目/迭代/需求的 list、create、edit、delete；权限配置的 permission_config、list；用户管理的 list、create、edit、delete。 |
| **测试人员 tester** | 仅查看：project.list、iteration.list、requirement.list。 |
| **普通成员 admin** | 仅查看：project.list、iteration.list、requirement.list。 |

实现位置：`backend/app/constants/permissions.py` 中 `DEFAULT_ROLE_PERMISSIONS`。数据库种子与废弃权限清理：`database/06_seed_role_permissions.py`。
