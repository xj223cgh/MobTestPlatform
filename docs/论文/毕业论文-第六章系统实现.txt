6  系统实现

系统实现章节在概要设计与详细设计的基础上，说明本系统在实际开发中所采用的核心技术、项目技术架构，以及主要操作界面与功能的具体实现方式，为读者提供从设计到代码落地的完整视图。


6.1  软件开发说明


6.1.1  核心开发技术

本系统采用前后端分离模式，以下简述几项核心运用技术。

（1）Vue。Vue 为渐进式 JavaScript 前端框架，支持组件化开发与响应式数据绑定，本系统采用 Vue 3，并配合 Vue Router、Pinia 等生态完成单页路由与状态管理。

（2）Flask。Flask 为 Python 轻量级 Web 框架，支持 RESTful 路由与 Blueprint 模块化，扩展生态丰富，本系统在此基础上提供 API 与 WebSocket 服务。

（3）MySQL。MySQL 为广泛使用的关系型数据库，本系统采用 MySQL 8.x 作为持久化存储，通过驱动与 ORM 与后端连接。

（4）Axios。Axios 为基于 Promise 的 HTTP 客户端库，支持请求与响应拦截、跨域等，本系统前端通过 Axios 统一封装与后端的 API 调用。

（5）Element Plus。Element Plus 为基于 Vue 3 的 UI 组件库，提供表单、表格、弹窗、消息等组件，本系统采用其构建一致的前端界面。

（6）SQLAlchemy。SQLAlchemy 为 Python ORM 框架，完成对象与关系型数据库的映射，本系统通过 Flask-SQLAlchemy 集成，实现数据访问层封装。

（7）Node.js。Node.js 为 JavaScript 运行时，提供 npm 包管理与前端工程化能力，本系统前端在 Node 环境下使用 Vite 进行开发与构建，满足 Vue 等前端技术的运行与打包需求。


6.1.2  项目技术架构

项目技术架构与第四章概要设计中的系统技术架构一致。系统采用 B/S 架构与前后端分离模式，在逻辑上划分为三层：表现层为 Vue 3 单页应用（由 Vite 构建），用户通过浏览器访问；业务逻辑层由 Flask 提供 RESTful API 与 Flask-SocketIO 提供 WebSocket 服务；数据访问层采用 SQLAlchemy ORM 与 MySQL 8.x，负责数据持久化。前后端之间通过 HTTP/JSON 进行接口调用，通过 Socket.IO 建立 WebSocket 长连接以接收实时消息推送；后端以 Blueprint 组织路由，统一经 ORM 访问数据库，不向外界直接暴露数据库。整体架构见图 6-1。

（2）后端目录与模块划分

后端以 Flask 应用工厂模式组织：在 app/__init__.py 中通过 create_app() 创建应用，依次加载配置、初始化扩展（db、login_manager、CORS、Session、SocketIO）、注册蓝图、注册错误处理，并在应用上下文中执行 db.create_all() 完成表结构同步。路由按业务域拆分为多个 Blueprint，与概要设计中的七大功能模块对应，便于分工与维护。核心目录结构见图 6-2。

图 6-2  后端核心目录结构

【标注说明】app 为应用包；models 定义 ORM 模型，routes 下按业务划分认证、用户、项目、设备、用例、脑图、任务、报告、评审、AI 任务、通知等路由；services 提供通知等可复用服务，utils 提供响应封装与异步任务管理等工具。

```
backend/
├── app/
│   ├── __init__.py          # 应用工厂 create_app、扩展初始化、蓝图注册
│   ├── config/              # 配置（如 default、development）
│   ├── models/
│   │   └── models.py        # 所有数据库模型（User、Project、TestSuite、TestCase 等）
│   ├── routes/              # API 路由蓝图
│   │   ├── auth.py          # 认证（登录、登出、验证码、找回/重置密码）
│   │   ├── users.py         # 用户管理
```

（3）前端目录与路由组织

前端采用 Vite + Vue 3 项目结构，页面组件按业务模块放置在 views 下（如 auth、project、device、testCase、testTask、report、user、system），路由在 router/index.js 中集中配置；登录、忘记密码、重置密码及脑图全屏/编辑器为独立路由，其余业务页面作为 Layout 的子路由，共享侧边栏与顶栏。路由守卫在 beforeEach 中完成登录校验与权限校验，与 Pinia 中的用户与权限状态联动。这样既保证了“操作系统界面”的统一布局，又明确了各功能对应的视图与路由，便于实现 6.2 节中的界面与功能描述。


6.2  操作系统界面和功能实现

本节根据系统实际实现，按功能模块说明主要操作界面、用户操作及页面呈现效果；在适宜位置标注应插入的界面截图（说明插入何种图即可），便于与正文对照。


（1）登录与认证。用户访问系统时首先进入登录页。页面中央为登录表单，提供“账号密码”与“邮箱验证码”两种登录方式；用户输入用户名与密码（或邮箱与验证码），可勾选“记住我”后点击“登录”。页面上方或一侧展示系统名称或 Logo，底部提供“忘记密码”链接。【此处插入图 6-3：登录页界面】点击“忘记密码”后跳转至忘记密码页，用户输入邮箱并获取验证码，提交后系统将重置链接发送至邮箱；用户通过邮件中的链接进入重置密码页，输入新密码并确认后完成重置。登录成功后，浏览器跳转至系统首页。


（2）主框架与首页。登录后进入主框架：左侧为垂直侧边栏，根据当前用户权限动态显示“首页”“项目管理”“迭代管理”“需求管理”“设备管理”“测试用例”“用例评审”“测试任务”“报告管理”等菜单项，以及“用户管理”“权限配置”“系统设置”“个人中心”“帮助中心”等（依权限可见性不同）；顶部为系统标题、消息通知铃铛图标（带未读数量徽标）和用户头像或用户名下拉菜单。【此处插入图 6-4：主框架布局与侧边栏】默认展示的首页为仪表盘，页面以统计卡片和图表形式展示项目数、用例数、任务数等汇总数据，图表由 ECharts 渲染。【此处插入图 6-5：首页仪表盘】


（3）项目管理与迭代、需求。项目管理页以表格形式列出项目，支持按名称、状态等筛选；每条记录可编辑、删除或点击进入详情。点击“新建项目”打开表单，填写项目名称、描述、负责人、成员等并提交。【此处插入图 6-6：项目管理列表页】项目详情页展示项目基本信息、关联的迭代与需求列表，以及用例数量、执行通过率等统计。【此处插入图 6-7：项目详情页】迭代管理页、需求管理页分别为迭代列表与需求列表的增删改查，界面为表格与表单组合，与项目、用例关联。


（4）设备管理。设备管理页以表格列出已登记设备，列包括设备别名、型号、系统类型、设备 ID、状态等；支持新建设备、编辑、删除，以及点击某设备进入详情。【此处插入图 6-8：设备管理列表页】设备详情页展示设备完整信息，并提供 ADB 操作按钮（如截图、重启）、无线连接（连接/断开）以及核心的投屏功能入口。【此处插入图 6-9：设备详情页（含投屏入口）】点击“投屏”后，系统启动设备屏幕镜像（基于 scrcpy），在独立窗口中实时显示设备画面，便于远程查看与操作。【此处插入图 6-10：设备投屏界面】


（5）测试用例与脑图编辑。测试用例管理页支持树形用例集与列表两种视图，可筛选项目、迭代等；可进入某用例集的“脑图预览”以只读方式查看脑图，或进入“脑图编辑器”进行编辑。【此处插入图 6-11：测试用例管理页（树形/列表视图）】脑图编辑器为独立全屏页面，中央为思维导图画布，支持节点增删改、展开折叠、撤销重做、搜索替换、标签与标记、版本历史与回退；保存后与后端同步，用例数据与脑图节点一一对应。【此处插入图 6-12：脑图编辑器界面】


（6）用例评审。用例评审模块包含多个功能页面与入口：待我评审、我发起的评审、最近评审，以及按用例集区分的评审历史等，用户可按维度查看与处理评审任务。【此处插入图 6-13：用例评审页（待我评审/我发起的评审/最近评审等）】支持发起新评审（选择用例集、评审人等）；进入某评审任务后，按用例逐条展示，评审人可对每条用例选择“通过”或“拒绝”，并查看历史记录。【此处插入图 6-14：评审任务详情页】


（7）测试任务与执行。测试任务页列出任务，支持新建、编辑、删除；新建时可选择任务类型（用例测试或设备脚本）、关联用例集与设备。【此处插入图 6-15：测试任务列表页】点击“执行”后，根据任务类型进入对应执行页：用例测试任务进入用例执行页，展示用例列表与步骤，执行人对每条用例选择执行结果（通过/失败/阻塞/不适用）并填写备注；设备脚本任务进入设备脚本执行页，展示脚本执行相关界面与结果。【此处插入图 6-16：用例执行页】【此处插入图 6-17：设备脚本执行页】两种任务均有对应的执行详情与结果记录。报告管理页展示报告列表，报告分为两种类型：与用例测试任务对应的用例测试报告（含用例执行结果统计），与设备脚本任务对应的设备脚本执行报告。【此处插入图 6-18：报告列表页】列表支持按任务类型筛选，点击某报告进入详情页查看对应类型报告内容，并支持导出 Excel、Word 等格式。【此处插入图 6-19：报告详情页（用例测试报告/设备脚本报告）】


（8）AI 生成用例。在测试用例管理或脑图编辑相关流程中，用户可上传需求文档并点击“AI 生成用例”。提交后页面展示任务进度（如进度条或百分比），完成后通过消息提示或顶栏通知告知用户，生成的用例出现在对应用例集中。【此处插入图 6-20：AI 生成用例上传与进度展示】


（9）用户管理、权限配置与系统设置。用户管理页（需相应权限）以表格展示用户列表，支持新建、编辑、删除、角色分配、密码重置、启用/停用。【此处插入图 6-21：用户管理页】权限配置页以表格或矩阵形式展示角色与权限埋点的对应关系，支持勾选后保存。【此处插入图 6-22：权限配置页】系统设置页包含系统名称、Logo、描述、密码策略、登录锁定时长、会话超时时长等配置项，以及用户个人设置。【此处插入图 6-23：系统设置页】


（10）消息通知。主框架顶栏右侧为消息铃铛图标，点击后展开下拉面板，展示通知列表；每条通知可标记已读、置顶，未读数量以徽标形式显示在图标上。【此处插入图 6-24：消息通知下拉面板】


（11）个人中心。个人中心页展示当前登录用户的基本信息（如用户名、邮箱、角色等），支持修改密码、维护个人设置等，是用户管理自身账户与偏好的入口。【此处插入图 6-25：个人中心页】

（12）帮助中心。帮助中心提供系统使用说明与操作指南等帮助内容，用户可通过侧边栏“帮助中心”入口进入；若前文功能结构图中未单独列出该子功能，可视为“用户与权限”或系统级辅助功能，在此处说明即可。【此处插入图 6-26：帮助中心页】


以上各点从用户操作与页面呈现角度描述了系统主要界面及功能体现，标注处可插入对应界面截图，与第四章功能结构、第五章详细设计相互对照，形成完整的系统实现说明。
