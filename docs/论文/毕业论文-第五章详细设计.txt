5  详细设计

详细设计在概要设计的基础上，对系统各功能模块的交互流程与关键步骤进行细化描述。本节采用时序图（Sequence Diagram）刻画用户、前端、后端 API、业务逻辑与数据库之间的调用顺序，便于开发实现与后续维护。各模块时序图遵循“参与者—请求—响应”的从左到右时间顺序，与项目实际接口与实现一致。


5.1  用户与权限模块详细设计

用户与权限模块负责身份认证、用户管理、角色权限配置及系统与用户设置。核心流程包括：账号密码登录（含失败锁定与会话超时）、获取当前用户与权限、用户增删改查与角色分配、权限配置的查询与更新。以下以登录流程和权限校验流程为代表给出时序图。

登录流程中，前端提交用户名与密码后，后端依次校验用户是否存在、是否被锁定、密码是否正确、账户是否启用，并从系统设置中读取会话超时时间；校验通过后创建会话并返回用户信息与权限码列表，供前端持久化与菜单渲染使用。

图 5-1  用户登录时序图

【标注说明】用户通过前端提交登录信息；后端校验用户与密码、锁定与激活状态，读取会话配置后创建会话并返回用户信息与权限列表。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库

    用户->>前端: 输入用户名、密码并提交
    前端->>后端: 提交登录请求 (POST /login)
    后端->>数据库: 查询用户信息 (User)
    数据库-->>后端: 用户记录
    后端->>后端: 校验密码、锁定与激活状态 (check_password)
    后端->>数据库: 查询会话配置 (SystemSetting)
    数据库-->>后端: 配置信息
    后端->>后端: 创建会话 (login_user)
    后端->>数据库: 查询角色权限 (get_user_permission_codes)
    数据库-->>后端: 权限列表
    后端-->>前端: 返回用户信息与权限
    前端-->>用户: 登录成功，跳转首页
```


权限校验与当前用户获取在每次进入需鉴权页面或调用敏感接口时发生：前端可先请求当前用户与权限以控制菜单与按钮，后端在需要时对接口进行权限校验。下图描述前端获取当前用户及权限、以及后端在受保护接口中的校验流程。

图 5-2  获取当前用户与权限校验时序图

【标注说明】前端请求当前用户信息与权限列表；后端在受保护接口中根据会话获取当前用户并校验权限码，不通过则返回 403。

```mermaid
sequenceDiagram
    participant 前端
    participant 后端
    participant 数据库

    前端->>后端: 获取当前用户或权限 (GET /current-user、/permissions)
    后端->>后端: 从会话获取 current_user (Flask-Login)
    后端->>数据库: 查询用户信息、角色权限
    数据库-->>后端: 用户、权限列表
    后端-->>前端: 返回用户与权限

    前端->>后端: 请求受保护接口（如用户管理）
    后端->>后端: 鉴权 (@login_required、权限埋点)
    alt 无权限
        后端-->>前端: 403 无权限
    else 有权限
        后端->>数据库: 执行业务查询/更新
        后端-->>前端: 返回业务数据
    end
```


5.2  项目管理模块详细设计

项目管理模块负责项目、迭代与版本需求的创建、查询、更新与删除，以及项目成员的维护。项目创建时可选指定负责人与成员，并触发对负责人或新成员的消息通知；迭代与版本需求挂载在项目下，供用例集与任务关联使用。以下给出项目创建与项目成员添加的时序图。

图 5-3  项目创建与成员添加时序图

【标注说明】前端提交项目信息与成员列表；后端创建项目并写入项目成员，可选通知负责人与成员；迭代与版本需求的创建流程类似，均依赖项目 ID 与当前用户。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 通知服务 as notify_users
    participant 数据库

    用户->>前端: 填写项目名称、描述、负责人、成员
    前端->>后端: 提交项目信息 (POST /api/projects/)
    后端->>数据库: 创建项目 (Project)、项目成员 (ProjectMember)
    后端->>通知服务: 通知负责人与成员 (notify_users)
    通知服务->>数据库: 写入 notifications
    通知服务->>通知服务: 实时推送 (emit)
    后端-->>前端: 返回项目信息
    前端-->>用户: 创建成功，跳转项目列表/详情
```


5.3  测试用例管理模块详细设计

测试用例管理模块包含用例集树、测试用例 CRUD、脑图编辑与同步、用例评审与 AI 生成用例。脑图保存时需进行版本冲突检测，并将脑图数据解析为用例同步至 test_cases 表；评审发起时为每条用例创建评审详情并通知评审人；AI 生成为异步任务，完成后通过通知服务告知用户。以下分别给出脑图保存与评审发起的时序图。

图 5-4  脑图保存与用例同步时序图

【标注说明】前端提交脑图 JSON 与客户端版本号；后端校验用例集类型与版本冲突，解析脑图生成用例列表并同步至数据库，保存脑图版本快照并更新用例集统计。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库

    用户->>前端: 编辑脑图后点击保存
    前端->>后端: 提交脑图数据 (PUT /api/mindmap/<suite_id>)
    后端->>数据库: 查询用例集 (TestSuite)
    后端->>后端: 校验类型与版本冲突
    alt 版本冲突
        后端-->>前端: 409 请刷新后重试或强制覆盖
    end
    后端->>后端: 解析脑图生成用例 (_parse_mindmap_to_cases、_sync_cases_to_db)
    后端->>数据库: 同步用例并更新套件与版本历史 (test_cases, MindmapVersion)
    后端-->>前端: 返回 suite_id、case_count、mindmap_version
    前端-->>用户: 保存成功
```


图 5-5  用例集评审发起时序图

【标注说明】发起人选择用例集与评审人后，后端创建评审任务与每条用例的评审详情，更新用例集评审状态并通知评审人。

```mermaid
sequenceDiagram
    participant 发起人
    participant 前端
    participant 后端
    participant 通知服务 as notify_users
    participant 数据库

    发起人->>前端: 选择用例集、评审人，发起评审
    前端->>后端: 发起评审 (POST .../initiate-review)
    后端->>数据库: 查询用例集与用例，创建评审任务 (TestSuiteReviewTask) 与评审详情 (TestCaseReviewDetail)
    后端->>数据库: 更新用例集 review_status
    后端->>通知服务: 通知评审人 (notify_users)
    通知服务->>数据库: 写入 notifications
    通知服务->>通知服务: 实时推送 (emit)
    后端-->>前端: 返回 review_task_id
    前端-->>发起人: 发起成功
```


5.4  设备管理模块详细设计

设备管理模块负责设备的登记、编辑、删除与列表查询，以及设备在线状态的主动刷新与 ADB 命令执行。设备状态通过调用 ADB（如 get-state）获取，ADB 命令接口接收命令类型与设备标识并执行相应子进程。以下给出设备列表查询与设备状态刷新的时序图。

图 5-6  设备列表查询与状态刷新时序图

【标注说明】前端请求设备列表时后端从数据库查询并返回；状态刷新时后端根据设备 ID 调用 ADB 获取实际连接状态并返回。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库
    participant ADB as ADB

    用户->>前端: 打开设备管理页 / 点击刷新状态
    前端->>后端: 请求设备列表或状态 (GET /api/devices 或 /<id>/status)
    alt 列表查询
        后端->>数据库: 查询设备列表 (Device)
        后端-->>前端: 返回设备列表
    else 状态刷新
        后端->>数据库: 查询设备信息
        后端->>ADB: 获取连接状态 (adb get-state)
        ADB-->>后端: device / disconnected
        后端-->>前端: 返回连接状态
    end
    前端-->>用户: 展示列表或状态
```


5.5  测试任务与执行模块详细设计

测试任务与执行模块实现任务的创建、与用例集/设备的关联、用例快照的生成、执行过程与结果记录，以及任务完成时自动生成报告并通知相关人员。创建用例执行任务时，系统根据关联的用例集获取用例列表并写入任务用例快照；执行人提交每条用例的执行结果后，可标记任务完成，此时系统自动生成报告并推送通知。以下给出任务创建与任务完成（含报告生成与通知）的时序图。

图 5-7  测试任务创建与用例快照时序图

【标注说明】前端提交任务名称、类型、用例集 ID、文件夹等；后端校验套件与文件夹，创建任务并关联用例或设备，对用例型任务写入用例快照后提交事务。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库

    用户->>前端: 选择用例集、设备等，创建任务
    前端->>后端: 提交任务信息 (POST /api/test-tasks)
    后端->>数据库: 校验套件与文件夹，创建任务 (TestTask)、关联用例或设备
    alt 用例型任务且有关联套件
        后端->>后端: 生成用例快照 (_save_task_case_snapshots)
        后端->>数据库: 写入任务用例快照 (TaskCaseSnapshot)
    end
    后端->>数据库: 提交事务 (commit)
    后端-->>前端: 返回 test_task
    前端-->>用户: 任务创建成功
```


图 5-8  任务完成与报告自动生成时序图

【标注说明】执行人提交最后一条执行结果或点击完成任务；后端更新任务状态为已完成，调用报告服务生成报告并落库，随后通知创建人/执行人。

```mermaid
sequenceDiagram
    participant 执行人
    participant 前端
    participant 后端
    participant 报告服务 as create_report_for_task
    participant 通知服务 as notify_users
    participant 数据库

    执行人->>前端: 填写执行结果并完成任务
    前端->>后端: 提交执行结果或完成 (POST .../executions/... 或 .../complete)
    后端->>数据库: 更新执行记录、任务状态为已完成
    后端->>报告服务: 生成报告 (create_report_for_task)
    报告服务->>数据库: 汇总执行记录与快照，写入 Report
    报告服务-->>后端: 返回 Report
    后端->>数据库: 提交事务
    后端->>通知服务: 通知创建人/执行人 (notify_users)
    通知服务->>数据库: 写入 notifications
    通知服务->>通知服务: 实时推送 (emit)
    后端-->>前端: 任务已完成
    前端-->>执行人: 完成提示
```


5.6  报告管理模块详细设计

报告管理模块负责测试报告的生成、存储与查询。报告可与任务一一关联，内容来源于任务执行记录与任务创建时的用例快照；支持任务完成后自动生成（见 5.5 节）与用户手动选择任务触发生成。报告数据接口优先返回已落库报告，若无则实时计算不落库。以下给出手动生成报告与获取报告数据的时序图。

图 5-9  报告手动生成与数据查询时序图

【标注说明】手动生成时后端仅对已完成任务调用 create_report_for_task 并落库；获取报告数据时优先查询已存储报告，若无则根据任务与执行记录实时生成数据返回（不写入数据库）。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant 后端
    participant 数据库

    用户->>前端: 选择已完成任务，点击生成报告
    前端->>后端: 触发生成 (POST /api/reports/generate/任务id)
    后端->>后端: 校验任务已完成，调用 create_report_for_task
    后端->>数据库: 写入 Report
    后端-->>前端: 返回 report_id、report

    用户->>前端: 打开报告详情
    前端->>后端: 请求报告数据 (GET /api/reports/任务id/data)
    后端->>数据库: 查询已落库报告 (Report)
    alt 已有落库报告
        后端-->>前端: 返回 summary、details
    else 无落库报告
        后端->>后端: 实时生成 (generate_test_case_report 等)
        后端-->>前端: 返回 summary、details，不落库
    end
```


5.7  消息通知模块详细设计

消息通知模块为各业务模块提供统一的通知创建与实时推送能力。业务侧调用 notify_users 后，服务先向 notifications 表写入记录，再通过 Socket.IO 向对应用户房间发送 notification 事件；前端在建立 WebSocket 连接时加入 user:{user_id} 房间，监听 notification 并更新未读数与列表。以下给出通知创建与实时推送的时序图。

图 5-10  消息通知创建与实时推送时序图

【标注说明】业务事件（如任务完成、评审待办、AI 生成完成）触发 notify_users；服务先批量写入 notifications 表，再向每个目标用户的 Socket.IO 房间 emit；前端已通过 connect 时 join_room 加入 user:{id}，收到事件后更新 UI。

```mermaid
sequenceDiagram
    participant 业务模块 as 任务/评审/AI等
    participant 通知服务 as notify_users
    participant 数据库
    participant SocketIO as Flask-SocketIO
    participant 前端

    业务模块->>通知服务: 发起通知 (notify_users)
    通知服务->>通知服务: 去重、排除操作者
    通知服务->>数据库: 写入 notifications
    通知服务->>SocketIO: 推送 (emit('notification', room='user:{id}'))
    SocketIO->>前端: 推送 notification 事件
    前端->>前端: 更新未读徽标与列表
    通知服务-->>业务模块: 返回通知 id 列表
```


图 5-11  前端连接 WebSocket 与接收通知时序图

【标注说明】用户登录后前端建立 Socket.IO 连接；后端在 connect 事件中校验登录状态并将客户端加入 user:{user_id} 房间，后续该用户的所有通知均发往该房间。

```mermaid
sequenceDiagram
    participant 用户
    participant 前端
    participant SocketIO as Flask-SocketIO
    participant 后端

    用户->>前端: 登录成功，加载主界面
    前端->>SocketIO: 建立连接 (connect)
    SocketIO->>后端: 校验登录 (current_user.is_authenticated)
    alt 未认证
        SocketIO->>前端: 断开 (disconnect)
    else 已认证
        SocketIO->>SocketIO: 加入用户房间 (join_room('user:{id}'))
        SocketIO-->>前端: 连接成功
        前端->>前端: 监听 on('notification')
    end
```
