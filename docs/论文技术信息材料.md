## 一、系统架构概述

本系统采用**前后端分离**的三层架构，分为：

```
MobTestPlatform/
├── frontend/          # Vue 3 前端应用（默认端口 8081）
├── backend/           # Flask RESTful 后端（默认端口 5000）
├── database/          # 数据库初始化脚本（MySQL）
├── escrcpy/           # 设备屏幕镜像工具（第三方，Electron）
└── start.py           # 一键启动脚本（multiprocessing 同时拉起前后端）
```

- **前端**：基于 Vue 3 的单页应用（SPA），通过 Vite 构建，与后端通过 RESTful API + WebSocket 通信。
- **后端**：基于 Flask 的 Python Web 服务，提供 JSON 格式 REST 接口，使用 SQLAlchemy ORM 操作 MySQL 数据库。
- **通信方式**：HTTP/HTTPS（REST API） + WebSocket（Socket.IO，用于实时消息推送）。
- **启动方式**：`start.py` 使用 Python `multiprocessing` 并行启动前后端，支持一键运行。

## 七、权限体系设计

### 7.1 角色层级

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| `super`（超级管理员） | 系统最高权限，拥有所有功能 | 全部 |
| `manager`（项目管理员） | 管理项目、迭代、需求、用例 | 可配置 |
| `tester`（测试人员） | 执行测试、管理用例 | 可配置 |
| `admin`（普通成员） | 基础查看权限 | 最少 |

### 7.2 埋点权限编码（部分示例）

| 模块 | 埋点编码 | 说明 |
|------|---------|------|
| 项目管理 | `project:access` | 访问项目模块 |
| 项目管理 | `project:create` | 创建项目 |
| 项目管理 | `project:edit` | 编辑项目 |
| 项目管理 | `project:delete` | 删除项目 |
| 迭代管理 | `iteration:access` | 访问迭代模块 |
| 需求管理 | `requirement:access` | 访问需求模块 |
| 用户管理 | `user:access` | 访问用户管理 |
| 用户管理 | `user:create` | 创建用户 |
| 权限配置 | `permission:access` | 访问权限配置 |

### 7.3 权限控制实现

- **前端**：Vue Router 路由守卫 `beforeEach` 中，读取 Pinia Store 中用户的 `permissions` 列表，与路由元信息 `meta.permissions` 比对，不满足则跳转 `/403`。
- **后端**：每个需要权限控制的 API 接口通过 `@login_required` 装饰器校验登录状态，敏感操作额外校验用户角色。

## 八、AI 生成测试用例流程

```
用户上传需求文档
        ↓
前端调用 POST /api/ai-tasks/generate-cases（传入文档内容 + 套件ID）
        ↓
后端创建异步任务（TaskManager），返回 task_id
        ↓
后台线程异步执行：
  1. 解析需求文档内容
  2. 构建结构化 Prompt（含需求文档 + 输出格式要求）
  3. 调用 SiliconFlow AI 接口（Qwen2.5-7B-Instruct，OpenAI 兼容格式）
  4. 解析 AI 返回 JSON（test_cases 数组）
  5. 生成用例编号（项目缩写-版本号-需求缩写+序号，如 PROJ-1.0.0-REQ001）
  6. 批量写入 test_cases 数据库表
  7. 完成后通过 SocketIO 推送通知给用户
        ↓
前端轮询 GET /api/ai-tasks/task-status/:taskId（获取进度 0~100%）
        ↓
任务完成，显示成功通知，用例自动出现在对应套件下
```

**AI 接口参数**：
- 模型：`Qwen/Qwen2.5-7B-Instruct`（可在 `.env` 中替换）
- 接口格式：OpenAI 兼容（`/v1/chat/completions`）
- 服务商：SiliconFlow（`https://api.siliconflow.cn/v1`）
- 温度参数：`temperature=0.3`（低随机性，保证稳定输出）
- 动态 Token 上限：根据文档长度动态计算，最大 16384 tokens

## 九、WebSocket 实时通知机制

- **服务端**：Flask-SocketIO，当 AI 任务完成、用例评审状态变更等事件发生时，调用 `notification_service.notify_users()` 向指定用户推送 Socket 事件。
- **客户端**：Vue 应用在 Layout 组件初始化时通过 Socket.IO Client 建立 WebSocket 连接，监听 `new_notification` 事件，实时更新通知徽标数。
- **Vite 代理配置**：开发环境下，`/socket.io` 路径由 Vite Dev Server 代理到后端 `http://127.0.0.1:5000`，支持 WebSocket 升级。
