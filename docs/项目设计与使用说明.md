# 移动端测试平台——项目设计背景与目标

在软件测试工作中，我注意到测试团队普遍依赖 Excel 或 Xmind 等管理用例，每次版本迭代都需要花费大量时间手动维护；特别是涉及移动端测试，通常我们的真机设备缺少统一管理，借用和状态跟踪全靠口头沟通，工作时需要在工作电脑和设备上来回切换；从需求到报告各个环节使用不同工具，数据无法互通；手写用例也很耗时，在测试环节的时间占比比较大的一些痛点。

基于以上问题，我以此为课题做了这个毕业设计。平台的目标是把用例管理、设备管理、测试执行和报告生成整合到一起，打通整个测试流程；同时引入大语言模型，支持根据需求文档自动生成测试用例，减少重复性工作，对测试流程进行提效；另外加入了角色权限体系，让平台能适应多人协作的实际使用场景。

---

## 核心功能模块说明

### 一、用例脑图编辑器

这是本平台的核心特色功能之一。在传统测试管理工具中，用例以表格或列表形式录入，结构层级不直观，不利于快速梳理测试思路。本平台引入了专用的**脑图式用例编辑器**，以思维导图的方式创建和管理测试用例。

**主要特点：**

- **以脑图方式录入用例**：测试人员可直接在脑图上添加节点，每个叶子节点对应一条测试用例，节点数据（名称、步骤、预期结果、优先级等）通过右键菜单或快捷键填写。
- **数据双向同步**：脑图保存时，后端自动解析脑图结构并同步写入 `test_cases` 数据库表；反之，若已有 AI 生成的用例数据，打开脑图时会自动从 `test_cases` 反推还原脑图结构。
- **多人编辑冲突检测**：采用版本号机制（`mindmap_version` 字段），保存时若版本号与服务端不一致，返回 HTTP 409，前端提示用户刷新或选择强制覆盖，防止多人同时编辑时互相覆盖。
- **版本历史与回退**：每次保存自动生成快照，单个用例集最多保留 30 条版本记录，支持一键回退到任意历史版本。
- **搜索与替换**：支持按关键词全文查找节点，并支持批量替换节点文本，适用于用例批量修改场景。
- **高级筛选**：可按节点类型、优先级（P0～P4）、标签、标记、涉及自动化、用例覆盖端、公私网海外等多维度筛选，快速定位目标用例节点。
- **展开/折叠控制**：支持全部展开、全部折叠、展开至指定层数等操作，方便大规模用例集的浏览。
- **撤销/重做**：标准的编辑器撤销（Ctrl+Z）与重做（Ctrl+Y）支持。
- **用例编辑状态管理**：用例集可标记为"编写中"或"已完成"，与评审流程联动。

### 二、AI 自动生成用例

上传需求文档（文本/Word/PDF），后台调用大语言模型（SiliconFlow 平台，Qwen2.5-7B-Instruct）异步解析并生成结构化测试用例，通过 WebSocket 实时通知完成状态，生成结果直接写入数据库并在脑图和列表中展示。

### 三、设备管理与投屏

支持 Android/iOS 设备的注册、状态跟踪（在线/离线/占用/维护）、ADB 命令代理、无线连接，以及通过 scrcpy 实现设备画面实时投屏，测试人员无需来回切换设备即可在平台内操作和查看设备屏幕。

### 四、测试任务与报告

测试任务支持用例测试和设备脚本两种类型，关联用例集后可在线逐条记录执行结果（pass/fail/blocked/not_applicable），完成后一键生成测试报告，支持 Excel 和 Word 格式导出。
